# Part 2 背景手册：从哈希负载到多签方案

> 本文档解释 Part 2 的研究动机和来龙去脉，帮助团队成员快速理解"为什么要做这个"。
> 具体的算法实现和代码细节请参阅 `README_CN_SECTION2.md`。

---

## 1. 整个项目在研究什么？

项目名叫 **"Observing Linear Hashing"**——研究对象是**线性哈希函数**。

所谓线性哈希函数，就是一个保持"加法结构"的映射 F：

```
F(a + b) = F(a) + F(b)
F(k · a) = k · F(a)
```

这个性质看起来简单，但它同时出现在两个看似无关的领域：

- **Part 1**：研究线性哈希的**统计性质**（数据分布均不均匀？）
- **Part 2**：利用线性哈希的**代数结构**构造密码学签名方案

两个部分研究的是**同一个数学对象**，只是底层的代数结构不同（F₂ vs Z_p），应用场景不同（负载均衡 vs 数字签名）。这就是 Part 1 到 Part 2 的逻辑主线。

---

## 2. Part 1 做了什么？

Part 1 在二元域 F₂ = {0, 1} 上研究线性哈希函数：

```
h(x) = M · x     （M 是随机二元矩阵，所有运算 mod 2）
```

研究的核心问题是经典的 **"balls into bins"（球入桶）** 模型：

- 把 m 个数据通过哈希函数扔进 2^l 个桶
- 问：**最满的那个桶有多满？**（即 max-load）

Part 1 用实验验证了理论预测的尾概率界：

```
P[max-load ≥ r · log(n) / log(log(n))] ≈ 1/r²
```

**结论**：F₂ 上的线性哈希函数分布足够均匀，max-load 的尾概率衰减符合理论预期。换句话说，**线性哈希函数作为哈希函数是合格的**。

这就引出一个自然的问题：线性哈希函数除了做哈希表，还能干什么？

---

## 3. 关键桥梁 — 指数映射就是线性哈希函数

这是连接 Part 1 和 Part 2 的**核心洞察**，来自 TZ23 论文。

在传统的 Schnorr 数字签名中，核心运算是：

```
x  →  x · G     （标量 x 乘以椭圆曲线基点 G）
```

仔细看这个映射的性质：

```
(a + b) · G = a·G + b·G     ← 加法同态
(k · a) · G = k · (a·G)     ← 标量同态
```

**这不就是线性哈希函数吗！** 和 Part 1 的 `h(x) = M·x` 在结构上完全一样，只不过：

| | Part 1 | Part 2 |
|---|---|---|
| 底层域 | F₂ = {0, 1} | Z_p（p ≈ 2²⁵⁵） |
| 函数形式 | h(x) = M·x（矩阵乘法） | F(x) = x·G（标量乘法） |
| 输出空间 | 二元向量 | 椭圆曲线上的点 |

TZ23 的贡献就是：**把 Schnorr 签名中的 `x → x·G` 抽象成"线性哈希函数"这个一般概念**，然后证明只要线性哈希函数满足一些安全性质，就能构造安全的签名方案。

所以 Part 1 到 Part 2 的跳转不是突兀的——**Schnorr 签名一直在用线性哈希函数，只是以前没人这么看待它。**

## 4. 多签是什么？为什么需要它？

### 场景

想象一个公司的数字钱包，需要 3 位高管共同授权才能转账。

**朴素做法**：每人各签一个签名，验证者逐一检查 3 个签名。
- 问题：签名数量随人数线性增长，链上存储和验证开销大。

**多签（Multi-Signature）**：3 个人合作产生**一个**聚合签名，验证者只需验证这一个签名。
- 优势：不管多少人参与，最终只有一个签名，验证一次就够。

这在区块链场景中尤为重要（比如 Bitcoin Taproot），因为链上空间非常宝贵。

### 当前最优方案：MuSig2

MuSig2（Nick, Ruffing & Seurin, CRYPTO 2021）是目前最高效的 Schnorr 多签方案：
- 只需 **2 轮通信**
- 第一轮**不依赖消息**（可以预计算）
- 基于标准的 Schnorr 签名结构

**但有一个问题**：MuSig2 的安全性证明依赖 **OMDL 假设**（One-More Discrete Logarithm），这是一个比标准离散对数（DL）假设**更强**的假设。更强意味着更有可能被攻破——如果 OMDL 不成立，MuSig2 的安全性就没有理论保障了。

**研究问题**：能不能构造一个和 MuSig2 一样高效的方案，但安全性只依赖**标准的 DL 假设**？

## 5. MuSig2-H 做了什么改进？

### 核心思路

TZ23 的方案叫 **MuSig2-H**（H 代表 Hash，即线性哈希函数），思路很直接：

> 把 MuSig2 中所有的 `x → g^x`（或 `x → x·G`）替换成一个更一般的线性哈希函数 F。

方案结构几乎和 MuSig2 一模一样，但这个"更一般的 F"给了安全证明更多操作空间。

### 为什么不能直接用 F(x) = x·G？

因为 `F(x) = x·G`（从 Z_q 到曲线群）是一个**双射**（一一对应），而 TZ23 的安全证明要求 F 必须是**非单射的**（存在碰撞，即不同的输入映射到相同的输出）。

直觉上：安全证明的核心技巧是利用 F 的碰撞来做归约。如果 F 没有碰撞，这个技巧就用不了。

### Pedersen 构造

解决办法是用 **Pedersen 承诺**作为线性哈希函数：

```
F(x₁, x₂) = x₁·G + x₂·Z
```

- 输入是**两个**标量（x₁, x₂），属于 Z_q²（q² 个元素）
- 输出是**一个**曲线点，属于 E(F_p)（q 个元素）
- 由鸽巢原理，必然存在碰撞 → **非单射** ✓

其中 Z 是一个独立于 G 的生成元（通过 hash-to-curve 透明生成，没有人知道 Z 相对于 G 的离散对数）。

密钥生成时，限制在 `D_key = Z_q × {0}` 上：`pk = F(sk, 0) = sk·G`，和标准 Schnorr 完全一样。

### 安全性为什么更强？

安全性的归约链如下：

```
标准 DL 假设
    ↓  （Pedersen 承诺的碰撞抵抗归约到 DL）
碰撞抵抗（CR）
    ↓  （TZ23 Theorem 1）
AOMPR（代数单次原像抵抗）
    ↓  （TZ23 Theorem 2）
MuSig2-H 不可伪造
```

对比 MuSig2：

```
OMDL 假设（更强，争议更大）
    ↓
MuSig2 不可伪造
```

MuSig2-H 的安全性最终归结到**标准 DL 假设**——这是密码学中研究最充分、最被信任的假设之一。代价是签名稍大（包含两个标量而非一个），但安全基础更加坚实。

## 6. Part 1 与 Part 2 对照总结

| | Part 1 | Part 2 |
|---|---|---|
| **底层域** | F₂ = {0, 1} | Z_p，p = 2²⁵⁵ − 19 |
| **线性哈希函数** | h(x) = M·x（二元矩阵） | F(x₁,x₂) = x₁·G + x₂·Z（Pedersen） |
| **输入空间** | F₂^u | Z_q² |
| **输出空间** | F₂^l | E(F_p)（椭圆曲线） |
| **研究角度** | 统计性质 | 密码学应用 |
| **核心问题** | 输出分布均不均匀？ | 签名能不能被伪造？ |
| **关键结论** | 尾概率 ≈ 1/r² | 基于标准 DL 假设可证安全 |

**一句话总结**：Part 1 验证了"线性哈希函数的基本性质是否可靠"，Part 2 说明了"既然可靠，就拿它来构造更安全的签名方案"。两部分合起来，是对线性哈希函数从理论到应用的完整研究。
